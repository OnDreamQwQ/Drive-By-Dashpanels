# 面板遥控终端 —— 设计与实施计划书（v2）

> v2 变更：放弃「镜像面板俯视图」，改为 **终端读模块 → 每个模块一个专用 2D 控件 → 玩家自己摆放**。
> 所有 API 结论均为 `javap` 实测（jar：`dashpanels-2.1+neoforge1.21.1.jar`、`dashpanelsextra-1.4.1.jar`）。

---

## 一、为什么镜像方案被否

`dashpanelsextra` 的 `PanelOverviewScreen` 是「把物理面板按 1:1 画成俯视图 + 转发真实鼠标」。
这条路有两个绕不过去的坑：

1. **必须知道朝向与格坐标**：墙面板、天花板面板的 `FACING` 不同，`getContentArea()` 也不一定是 16 高，
   命中判定用模块本地 `getShape()` 就会点偏。
2. **拖拽必须借客户端输入**：它靠 `MinecraftInputInvoker`、`MouseHandlerAccessor` 两个 mixin
   把点击灌回游戏，与 `cursorEnabled`、ESC、聊天框互相打架。

新方案把这两条**全部删掉**：控件是我们自己画的矩形，命中是自己算的，不需要知道面板在哪里、朝哪边。

## 二、先摆出三个硬约束（决定方案边界，别指望绕过）

这三个是 `javap` 查出来的接口事实，不是保守估计：

### 2.1 `IOutput` 只能写，读不出当前值

```java
public interface IOutput { void setAnalog(int); }          // 没有 getter
public interface IMultiOutput { void setValues(BiConsumer<String, AnalogRunnable>); }
```

所以「数码管现在显示几」、 「灯泡现在亮不亮」**接口层面拿不到**。
只有两个内置显示模块的字段是 public，可以兜底读：

| 类 | 可读字段 |
|---|---|
| `moth.boxxed.panels.content.modules.IndicatorBulbModule` | `public boolean lit`、`public DyeColor color` |
| `moth.boxxed.panels.content.modules.SevenSegmentModule` | `public String display`、`public DyeColor color` |

### 2.2 `IInput` 只能读，设不进去

```java
public interface IInput { int getAnalog(); }               // 没有 setter
```

所以**控件不能"把拉杆推到 7"**，只能**模拟玩家右键那个模块**：

```java
public InteractionResult onUse(Level level, Player player);                    // 2 参，可用
public InteractionResult onUse(ModuleHitResult hit, Level, Player);            // 3 参
public ItemInteractionResult onItemUse(ItemStack, Level, Player);              // 3 参
public ItemInteractionResult onItemUse(ModuleHitResult, ItemStack, Level, Player);
```

这正是 `PanelOverviewUsePacket` 的做法（它调的就是 2 参 `onUse`）——**能确定的只有"点一下"**。

### 2.3 拖拽类模块没有可编程入口

拉杆、旋钮、滑块是「按下—拖动—松开」，`onUse` 只给一次回调。所以：

- 可用：**点一下就生效**的模块（按钮、开关、复位灯、指示灯）
- 不可用：需要拖动的（旋钮、滑块、拉杆的连续拖动）

代码里给它们降级成「单击」，并在控件上画一条提示标记，别让玩家以为坏了。

## 三、新架构

```
           线缆网络 (ModulesNetwork)
面板 A ─┐                        ┌─→ 模块清单：名字 / IO 类型 / 多路子键
面板 B ─┼── 面板遥控终端(方块) ──┤
面板 C ─┘         ↑              └─→ 布局表：哪个模块放在画布哪一格、用什么控件
              潜行右键
                  │
            面板遥控器(物品)  ── 右键 ──→ 2D 控件台界面
```

### 3.1 模块清单怎么来（这部分几乎是白捡的）

`ModuleMap extends LinkedHashMap<String, Module>`（**有序**，上一版担心的"遍历顺序不稳"是我查错了），
并且自带官方分类器：

```java
public List<ModuleIOInfo> filterIOModules();           // 名字 + 类型 + 多路子键，一次给全
public static ModuleIOType ModuleIOType.decide(Module); // INPUT / OUTPUT / MULTI_INPUT / MULTI_OUTPUT
```

`ModuleIOInfo` 是 record，还带 `STREAM_CODEC` —— **可以直接塞进网络包发客户端**，不用自己写序列化。

所以服务端每 tick（或每次打开）扫一遍网络成员：

```java
for (ModulesNetworkMember member : network.members) {
    if (!(member instanceof AbstractPanelBlockEntity panel)) continue;
    for (ModuleIOInfo info : panel.getModules().filterIOModules()) {
        // info.name() / info.type() / info.multiExtension()
    }
}
```

### 3.2 控件类型表

先按 `ModuleIOType` 分两大类，再按类名细化（字符串包含匹配，避免硬依赖内容类）：

| 条件 | 控件 | 交互 |
|---|---|---|
| `INPUT` 且类名含 `Button` | **按钮** | `onUse` |
| `INPUT` 且类名含 `Switch` / `Lever` | **开关** | `onUse` |
| `INPUT` 且类名含 `Knob` / `Dial` / `Slider` / `Valve` | **滑块（降级）** | 只发一次 `onUse`，标注「拖动可能无效」 |
| `INPUT` 其它 | **通用单击** | `onUse` |
| `OUTPUT` 且类名含 `Bulb` | **指示灯** | 只读，`lit` |
| `OUTPUT` 且类名含 `SevenSegment` | **数字显示** | 只读，`display` |
| `OUTPUT` 其它 | **数值框** | 只读，拿不到值就显示 `—` |
| `MULTI_INPUT` / `MULTI_OUTPUT` | 每个子键**拆一个**控件 | 同上 |

表里没命中的模块一律给「通用单击 / 数值框」，**不漏模块**——这是"读取所有模块信息"的兜底。

### 3.3 布局

- 画布：**16 列 × 9 行**，一格 8 GUI 像素；控件占整数格（最小 2×1，最大 16×2）。
- **共享布局**：存在终端方块实体的 NBT 里（`dbd:layout`），不是每个玩家一份。理由：这是工厂里的公共操作台，不是个人 HUD。
- **首次打开自动排版**：布局为空时，按面板、模块顺序从左上角填坑（每行放 4 个），一次写回服务端。
- **编辑模式**：进界面后按 `Tab` 切编辑态，鼠标拖动移动 / 右下角拖动缩放 / `Del` 删除 / 松手即发保存包。
  服务端校验：坐标在画布内、不重叠、引用的模块仍然存在、控件总数 ≤ 128。

### 3.4 值的同步

服务端每 **2 tick** 收集一次所有已放置控件的值，**只发变化的差值**：

```java
record ModuleState(BlockPos panel, String module, String subKey, int analog, String text)
```

客户端收到后只改那几个控件，不重画整屏。屏幕关闭即退订（`ContainerLevelAccess` 不在时用玩家集合维护）。

### 3.5 协议（服务端权威，客户端不做任何世界查询）

```
C→S  OpenTerminalPacket(BlockPos terminal)
S→C  TerminalSnapshotPacket(BlockPos terminal,
                            List<PanelEntry> panels,      // 面板坐标 + 显示名
                            List<ModuleEntry> modules,    // panel + ModuleIOInfo + 当前值
                            List<WidgetEntry> layout)     // 已保存的布局
C→S  TerminalActionPacket(BlockPos terminal, BlockPos panel, String module, String subKey,
                          byte action, int arg)           // CLICK / SET_ANALOG
C→S  TerminalLayoutPacket(BlockPos terminal, List<WidgetEntry> layout)
S→C  TerminalStatePacket(BlockPos terminal, List<ModuleState>)
```

服务端处理 `TerminalActionPacket` 的校验顺序（每步失败都只回动作栏，不抛异常）：

1. 玩家手里的物品是 `panel_remote`，其组件里的终端坐标 == 包里的 `terminal`；
2. 终端方块实体存在，`network.members` 里含包里的面板；
3. 模块名在该面板 `getModules()` 中存在；
4. `CLICK` → 要求模块是 `INPUT`/`MULTI_INPUT`，调 `onUse(level, player)`，再 `panel.setChanged()` + `panel.blockChanged()`；
   `SET_ANALOG` → 要求模块是 `OUTPUT`/`MULTI_OUTPUT`，`setAnalog(clamp(arg,0,15))`，同样 `setChanged`。
5. 动作频控：同一玩家 1 tick 最多 4 次（防止脚本刷）。

### 3.6 注册清单

| 类型 | id | 备注 |
|---|---|---|
| 方块 | `panel_remote_terminal` | `FACING` + 四面可接线缆 |
| 方块实体 | 同上 | `extends ModulesNetworkMember`（沿用 0.1.6 链路中心样板） |
| 物品 | `panel_remote` | 单堆叠，`DataComponent` 存「维度 + 终端坐标」 |
| 包 | 4 个 | 见 3.5 |

## 四、`panel viewer` 的 bug 清单（作为"不要这么写"的对照）

| # | 问题 | 机理 |
|---|---|---|
| 1 | `onUse` 被调两次 | 客户端 `mouseClicked` 先调，再发包让服务端再调一次 |
| 2 | 面板列表只在客户端扫 | `connectedPanels()` 纯客户端，区块没加载就退化成单块；服务端零校验 |
| 3 | 最多 5 块且必须同方块类型 | `collectNeighbors` 里 `distance <= 2` 写死 + `getBlock()` 相等才继续 |
| 4 | 命中忽略面板朝向 | 用模块本地 `getShape()`，墙/天花板面板点偏 |
| 5 | 层叠顺序 | ~~遍历顺序不稳~~ **（此条作废：`ModuleMap` 是 `LinkedHashMap`，顺序稳定且等于插入顺序）** |
| 6 | 拖拽靠转发真实鼠标 | `MinecraftInputInvoker` / `MouseHandlerAccessor` 与 `cursorEnabled`、ESC、聊天框互相打架 |
| 7 | 区块卸载后界面空壳 | `render` 里 `anchor == null` 只做兜底 |
| 8 | 被动 HUD 状态残留 | `showPassive` / `activatePassive` / 死亡、切维度时没清 |

新设计里 #2 #3 #4 #5 直接不存在（界面数据全服务端下发、没有俯视图）、#6 不做、#7 由"快照含面板名 + 状态包"覆盖、#8 不做。

## 五、分阶段实施

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **P1** | 方块 + 物品 + 注册 + 绑定/解绑 + 模块清单快照 + **纯文字列表界面** | 远处右键遥控器，能看到该网络所有面板与模块名、IO 类型、子键；拆终端后提示失效 | 1 天 |
| **P2** | 控件渲染（按钮 / 开关 / 指示灯 / 数字 / 通用）+ 首次自动排版 + `TerminalStatePacket` 值同步 | 界面显示与真实面板一致；改真实面板上的开关，界面立刻跟着变 | 1 天 |
| **P3** | `TerminalActionPacket` 点击执行 + 频控 + 五种失败提示 | 站在 200 格外点按钮，面板上的指示灯真的亮；**只亮一次** | 1 天 |
| **P4** | 布局编辑（拖动 / 缩放 / 删除 / 网格吸附 / 保存校验） | 摆完退出重进，布局还在 | 1 天 |
| **P5** | 边界：区块卸载 / 模块被删 / 多面板 / 两人同开 / 终端被拆 / 遥控器丢失 | 每项只有动作栏提示，不崩、不卡界面 | 半天 |
| **P6** | 可选：控件颜色与图标、布局模板导出粘贴、`SET_ANALOG` 反向驱动显示模块 | — | 待评估 |

版本号从 **0.2.0** 起。

## 六、测试清单

- [ ] 潜行右键终端 → 绑定提示；`F3+H` 能看到物品组件里的维度 + 坐标
- [ ] 退出重进 → 绑定还在
- [ ] 8 格 / 64 格 / 200 格外右键遥控器 → 都能打开
- [ ] 纯文字列表里模块数量 == 面板上实际数量（含多路子键）
- [ ] 首次打开自动排版 → 每个模块都有控件，且不重叠
- [ ] 真实面板上拨动开关 → 界面控件状态同步
- [ ] 点界面里的按钮 → 面板上指示灯亮，且只触发一次
- [ ] 点旋钮类 → 提示「该模块需要拖动，远程可能无效」
- [ ] 界面里把控件拖到别处 → 退出重进位置保持
- [ ] 拖到画布外 / 与别的控件重叠 → 被拒绝并有提示
- [ ] 拆掉一个模块 → 刷新后该控件变为「模块已移除」占位
- [ ] 拆掉终端 → 再右键遥控器 → 「终端已失效」且绑定被清
- [ ] 剪断终端与面板之间的线缆 → 提示「终端未接入面板网络」
- [ ] 终端区块卸载 → 打开被拒，不卡界面
- [ ] 两人同时开同一终端 → 各自独立；一人改布局，另一人重开才看到

## 七、风险与未验证项

| 风险 | 说明 | 应对 |
|---|---|---|
| 显示模块的值读不到 | `IOutput` 无 getter，只有两个内置类有 public 字段 | P2 用 `instanceof` 兜底这两类；其余显示 `—`；后续可加配置项声明「哪个 mod 的哪个类哪个字段可读」 |
| `onUse` 语义不统一 | 有的模块把逻辑写在客户端（如 `PanelViewModule`），服务端调无效 | P3 逐模块实测，建一张白名单表；不在表里的模块控件置灰并标「远程不可用」 |
| 终端加入网络的前提 | 「用线缆接到面板」这条是从 0.1.6 行为推的**假设** | P1 第一件事：游戏里确认 `network.members` 非空 |
| 布局数据量 | 128 控件 × 6 字段 ≈ 几 KB NBT | 可接受；用 `CompoundTag` 列表，不落盘到每个玩家 |
| 权限 | 遥控器本身就是钥匙，谁绑上都能操作 | 第一阶段就这样；若需要，P5 给终端加一个"所有者"字段 |
