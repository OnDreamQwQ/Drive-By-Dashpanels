# 模型制作手册 —— 面板遥控终端

这份手册讲两件事：**你要产出哪两个模型**、**每个模型的硬性要求**。
按这份手册做出来的东西不需要改任何代码就能生效——文件名是固定的，我这边靠文件名找。

---

## 0. 两个东西，两条路

| 项目 | id | 现在的占位 | 你要覆盖的文件 |
|---|---|---|---|
| 遥控器（手持物品） | `panel_remote` | 直接复用 Create 的无线红石遥控器模型 | `models/item/panel_remote.json` |
| 接收器（方块） | `panel_remote_receiver` | 面板链接器模型 + 换色贴图 | `models/block/panel_remote_receiver.json`<br>`textures/block/panel_remote_receiver.png` |

### 两个占位现在长什么样

**遥控器**：`models/item/panel_remote.json` 只有 48 字节：

```json
{
  "parent": "create:item/linked_controller"
}
```

也就是**外观和 Create 的无线红石遥控器完全一致**，你不需要画任何东西它就能用。要做自己的外形，把上面这行 `parent` 整个替换成 Blockbench 导出的模型即可。

**接收器**：`models/block/panel_remote_receiver.json`（4,138 字节）是 dashpanels 面板链接器的**原样拷贝**，只把命名空间从 `dashpanels:` 换成了 `drive_by_dashpanels:`。贴图 `textures/block/panel_remote_receiver.png`（32×32，653 字节）是把面板链接器贴图的**红蓝通道对调**得到的，所以：

- **面板链接中心** = 琥珀/棕色（`panel_link_center.png`，950 字节）
- **接收器** = 蓝青/青色（`panel_remote_receiver.png`，653 字节）

两个方块现在靠颜色就能分开。但形状还是一模一样，建议你按第 4 节改一下。

## 1. 为什么必须区分

这两个方块功能完全不同，长得一样会让玩家一直放错：

| 方块 | 干什么 | 玩家怎么用 |
|---|---|---|
| 面板链接中心 | 把面板模块的值**送到线缆上** | 线缆插在它身上 |
| 接收器 | 接收**遥控器**的指令，把面板投影到界面 | 遥控器和它绑定 |

建议区分方式（形状差异比颜色更可靠，色弱玩家也能认）：**接收器去掉一组天线**，因为「中心」是往外发信号的（有天线合理），接收器是被遥控的，天线少一点更符合直觉。

## 2.5 把现成模型导进 Blockbench 改（最省事的做法）

这两个模型都是别人画的美术，许可证不允许我放进仓库再分发，所以我已经把它们解到仓库外的临时目录：

```
D:\UserData\Documents\deepseek-harness\default-workspace\_models\
├── linker\                            dashpanels 的面板链接器（接收器的原型）
│   ├── control_link.json              4,102 B  ← 导入这个
│   ├── control_link.png               32×32 主贴图
│   └── metal.png                      364 B，金属面
└── remote\                            Create 的无线红石遥控器（遥控器的原型）
    ├── linked_controller_item.json    5,472 B  ← 导入这个（真正有几何的）
    ├── linked_controller.json         52 B     只是别名，别导
    ├── linked_controller.png          物品贴图
    └── redstone_antenna.png           天线贴图
```

### 步骤（两个模型一样）

1. Blockbench → **新建项目** → 格式选 **Java Block/Item**
2. `文件 → 导入 → 模型`，选上表里标「导入这个」的 json
3. 打开右侧 **纹理** 面板 → `导入纹理`，把 PNG 拖进去
   - **纹理名必须和模型里写的完全一样**。链接器那份用 `dashpanels:block/control_link` 和 `dashpanels:block/metal`，导入后在 BB 的纹理列表里把它们改成这两个字符串
   - 遥控器那份用 `create:item/linked_controller` 和 `create:block/redstone_antenna`
   - 名字对不上时 BB 会显示成紫黑格，但**几何不会坏**，改名后立刻恢复
4. 改几何。**不要动 UV 布局**，除非你也重画贴图
5. 导出：

| 做哪个 | 导出为 |
|---|---|
| 接收器 | `文件 → 导出 → Java Block/Item Model` → `panel_remote_receiver.json` |
| 遥控器 | `文件 → 导出 → Java Block/Item Model` → `panel_remote.json` |

导出后丢给我，剩下三件事我做：把纹理引用改成 `drive_by_dashpanels:` 命名空间、补回 `ambientocclusion` / `render_type`、检查 `display` 块。

所以你**不用管命名空间**，但别删 `display`、别改 `texture_size`、别把 `rotation.angle` 设成非 0。

### 一个提醒

`control_link.json` 的天线做到 y=19，越界了（方块只有 0~16）。BB 里能正常显示，游戏里也能画出来，但会伸进上方方块的空间。你在 BB 里把它压到 y≤16 的时候，顺手就和面板链接中心区分开了。

## 3. 遥控器（物品模型）

### 现在的结构

`models/item/panel_remote.json` 是个「别名」，指向 Create 的模型。物品图标就是 Create 那个遥控器。

### 做自己的外形

1. Blockbench → 新建 → **Java Block/Item**
2. 建模（建议 16×16 或 32×32 网格，物品别做太大）
3. 贴图放到 `textures/item/panel_remote.png`
4. `文件 → 导出 → Java Block/Item Model`，**覆盖** `models/item/panel_remote.json`（覆盖后原来的 `parent` 行自然消失，这是对的）

### 硬要求

- **必须自带 `display` 块**（第三人称左右手、第一人称左右手、ground、gui、fixed）。丢了它，物品拿在手上会歪、在物品栏里会变成巨大的方块。
  - 想省事：从 `create:item/linked_controller` 那份的 `display` 抄过来，比例比较合适。
- 模型里贴图写全名：`"texture": "drive_by_dashpanels:item/panel_remote"`，不要写 `#0` 除非你也定义了 `"0"`。
- `texture_size` 和 PNG 实际尺寸必须一致，否则贴图会错位。
- 元素 `rotation` 的 `angle` 保持 **0**（除非你确实要一个固定的倾斜件）。

### 想照抄 Create 遥控器的比例

Create 的模型是 3 个天线片 + 主体 + 按钮，已经解到 `_models\remote\linked_controller_item.json`，直接 `导入 → 模型` 打开再改，比自己从零搭快。

## 4. 接收器（方块模型）

### 现在的结构

4,138 字节，10 个元素：

| # | 形状 | 尺寸 |
|---|---|---|
| 0 | 底座 | `[1,0,1]` → `[15,7,15]`，四面用主贴图，上下用 metal |
| 1 | 台面 | `[2,7,2]` → `[14,12,14]`，只有上面用主贴图 |
| 2-4 | 天线组 A | 竖直片 + 顶帽，x 9~12 / z 4~7，**高到 y=19** |
| 5-7 | 天线组 B | 十字交叉的另一组，x 4~7 / z 9~12，**高到 y=19** |

⚠️ **y=19 是越界的**（方块只有 0~16）。这是 dashpanels 原模型就这么写的，游戏里能显示但会伸进上方方块的空间。你改的时候把天线压到 y≤16。

### 硬要求

| 项 | 要求 |
|---|---|
| `format_version` | 保持 `"1.9.0"` |
| `texture_size` | `[32, 32]`，贴图必须 32×32 |
| `ambientocclusion` | `false`（别改，改了面上会出现脏阴影） |
| `render_type` | `cutout_mipped`（丢了我在代码里补，但最好别丢） |
| 几何范围 | x 和 z 都在 1~15 内，y 在 0~16 内 |
| 贴图槽 | 只用 `#0`（主贴图）和 `#1`（metal），`particle` 用 metal |
| 每个面 | 必须同时有 `uv` 和 `texture` |
| `display` 块 | **不要动**，物品栏/手持显示靠它 |
| 元素 `rotation.angle` | 保持 0 |

`#1`（metal）的 UV 现在是 `[1,1,15,15]`，相对 32 网格——这是 dashpanels 原样，**别自己改**，改了金属面会变大变小。

### 建议的改法（三选一）

- **a) 只留一组天线**：删掉元素 5、6、7 和对应的 group（`groups` 里第二个 `"antenna"`）。10 个元素变 7 个，立刻和链接中心区分开。
- **b) 加一块屏**：台面中间挖一个 6×3 的暗色面（用主贴图画一块深色屏），侧面加一道横向线缆槽。
- **c) 顶部换成接线柱**：把两组天线都删掉，改两根 y 12~14 的短柱。

**我建议 a**：改动最小、几乎不会出错，而且「天线少一根」是玩家一眼能看出来的差别。

### 贴图

`textures/block/panel_remote_receiver.png` 现在是**红蓝对调**版的链接器贴图（青蓝色调）。你可以在这张上继续改，也可以重画。

⚠️ 重画时**别整个换色调**到和链接中心一样——两个方块必须一眼可分。

## 6. 常见坑

| 症状 | 原因 |
|---|---|
| 方块显示成紫黑格子 | 贴图路径拼错，或 PNG 没放到 `textures/` 下 |
| 贴图位置错乱、拉花 | `texture_size` 和 PNG 实际尺寸不一致 |
| 物品栏里图标是个巨大的方块 | 物品模型缺 `display` 块 |
| 拿在手上歪着/浮空 | 同上，`display` 的 `firstperson` / `thirdperson` 丢了 |
| 方块边缘闪烁 | 两个元素共面（z-fighting），把其中一个错开 0.01 |
| 某个面全黑或全透明 | 那个面缺 `texture`，或者 `uv` 反了（`uv` 要左上→右下） |
| Blockbench 里好看、游戏里错位 | 用了非 0 的 `rotation.angle`，或元素超出 0~16 |
| 物品拿在手里像方块 | 物品模型导成了 block 格式（Java Block/Item 才对） |
